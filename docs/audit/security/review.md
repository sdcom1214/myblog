기준 커밋은 `101f4f75cdafe8753ddc9e1acadfcc8f70506047`입니다. Node.js 서버, 브라우저 HTML 출력, 저장 파일, 로그인·세션·OAuth 코드, 온라인 대전·선수/팀 소유권, 파일 제공과 npm 의존성을 검토했습니다. 확인한 문제를 수정하고 임시 SQLite·실제 Chromium에서 재검증했습니다.

## 추가 보호와 확인 사항

- 빌드 서버와 개발 화면에 CSP, `nosniff`, 프레임 삽입 차단, Referrer/Permissions 정책을 적용했습니다. 스크립트는 같은 출처만 허용합니다. 능력치 막대 등 기존 인라인 스타일 때문에 스타일에는 `unsafe-inline`을 유지하며, 스크립트의 `unsafe-inline`/`unsafe-eval`은 허용하지 않습니다.
- `NODE_ENV=production`에서 별도 재정의가 없으면 Secure 쿠키와 HSTS를 활성화합니다. HTTPS 모드에서는 같은 호스트의 HTTP Origin 쓰기도 거부합니다. 실제 HTTPS 역프록시 배포에는 `COOKIE_SECURE=true`를 명시하는 실행 예시를 문서화했습니다.
- 개발 API는 기본적으로 127.0.0.1에만 바인딩합니다. Vite의 파일 제공에서 `.local`, `.git`, `.env`, 인증서와 도구 설정 디렉터리를 거부합니다. 기존 호스트 허용 목록도 유지합니다.
- JSON 5MB 제한과 객체/명령/식별자/스쿼드 검사를 적용했습니다. 요청 조각을 합친 뒤 UTF-8로 해석해 분할된 한글이 깨지지 않도록 했습니다.
- OAuth 시작에 요청 제한과 만료 상태 정리를 추가했습니다. 이메일 검증 값은 정확히 `true`여야 하며, 다른 Google 식별자가 연결된 계정을 같은 이메일로 사용하지 못하도록 검사합니다. state·브라우저 쿠키·PKCE를 사용하는 기존 흐름도 검토했습니다.
- SQL 값 바인딩, scrypt 비밀번호 저장, 무작위 세션과 해시 저장, HttpOnly/SameSite 쿠키, 로그인 제한, Origin/Fetch Metadata 검사, 저장 revision·대전 변조 방어, 선수·팀 소유권 확인을 검토하고 회귀 테스트했습니다.
- 현재 Git 추적 파일에서 주요 개인키·AWS 키·GitHub/OpenAI 토큰 패턴을 검색했으며 일치 항목이 없었습니다. SQLite와 실제 `.env`는 Git에서 제외되어 있습니다.

## 검토 범위의 한계

이번 결과는 저장소 코드와 이 클라우드 실행 환경의 검토입니다. 외부 배포의 TLS/역프록시·영구 볼륨 접근권한, 실제 Google 계정의 로그인, 인스타그램/iOS 실기기, 모든 Git 이력과 외부 비밀 저장소를 검사한 결과는 아닙니다. 운영 환경은 HTTPS와 Secure 쿠키 설정을 사용해야 합니다.

특훈의 타이밍·반응시간은 클라이언트가 측정합니다. 점수는 서버가 입력을 검사해 계산하지만 자동화 도구나 위조한 조작 시간까지 증명하는 방어는 포함하지 않습니다. 현재 요청 제한은 서버가 보는 접속 주소를 기준으로 하며 임의의 `X-Forwarded-For`를 신뢰하지 않습니다. 실제 서비스의 사용자 수에 맞춘 프록시/WAF 제한과 부하 검증은 별도 범위입니다. 알려진 의존성 취약점 0개가 모든 보안 문제가 없다는 의미는 아닙니다.
