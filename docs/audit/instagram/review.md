# 인스타그램 내장 브라우저 호환성 검토

2026-10-11 · `sdcom1214/myblog`

## 변경

- 커리어 카드는 실제 PNG를 데이터 이미지로 표시합니다. 인스타그램에서는 화면을 이동시키는 다운로드 대신 이미지 길게 누르기 안내를 제공합니다. 사진 저장 메뉴가 없는 앱 버전에서는 외부 브라우저 이용 방법과 복사할 게임 주소를 표시합니다. 일반 브라우저의 PNG 다운로드와 지원 기기의 파일 공유는 유지합니다. 다운로드 요청을 저장 완료로 표현하지 않습니다.
- `localStorage` 속성 접근, 읽기, 쓰기가 거부되거나 용량이 가득 차도 메모리에서 플레이할 수 있습니다. 임시 저장 상태를 표시하고, 기기 쓰기 실패가 계정의 서버 저장을 중단시키지 않도록 했습니다. 기존의 손상된 저장 파일 보존·백업 처리는 유지합니다.
- 저장된 계정 캐시는 인증 후 서버에서 복원합니다. 쿠키가 사라지거나 기기 저장을 지울 수 없는 상태에서 로그아웃해도 이전 계정 기록이 비회원 기록으로 표시되지 않게 했습니다.
- 로그인 응답 후 세션 쿠키가 실제로 유지되는지 확인합니다. 쿠키가 거부되면 외부 브라우저 로그인 안내를 표시합니다. 인스타그램·Facebook 내장 브라우저에서는 Google 인증을 외부 브라우저로 안내하고 이메일 로그인은 제공합니다.
- 포인터 캡처가 실패해도 문서 수준의 이동·종료 이벤트로 사인과 킥 입력을 마칩니다. 포인터 이벤트가 없으면 터치·마우스 입력을 사용합니다. 서명 종료 시 터치한 SVG를 즉시 교체하지 않고 계약 버튼 상태만 갱신합니다.
- 앱이 백그라운드로 이동하면 진행 중인 특훈을 멈추고 같은 시도를 다시 시작하게 합니다. 모바일 키보드와 화면 높이 변경에 맞춰 프레임 높이를 조절하며 입력 필드의 iPhone 자동 확대를 줄입니다.
- PNG 생성은 최신 `roundRect()`에 의존하지 않으며, 글꼴·로고 로딩에 시간 제한을 두고 로고가 없으면 구단 약칭을 사용합니다.

## WebGL 판단

현재 특훈 9종은 작은 HTML/CSS 화면과 입력·타이밍 처리로 동작합니다. 카드 생성에는 Canvas 2D를 사용합니다. WebGL을 추가할 3D 장면이나 대량 그래픽 작업이 없어 이번 변경에서는 도입하지 않았습니다. WebGL 도입은 내장 브라우저의 다운로드·저장·인증 제한을 해결하지 않습니다. 검증에서는 WebGL 컨텍스트를 사용할 수 없게 한 상태에서도 게임과 PNG 생성을 실행합니다. 기존 특훈 디자인과 서버 점수 계산은 유지합니다.

## 검증 방법

`tests/browser-instagram.py`는 빌드된 실제 HTTP 서버와 격리된 SQLite DB에 접속합니다. 저장 파일을 조작하거나 엔진을 직접 호출하지 않고 가입·선수 생성·유소년 진행·계약·각 특훈의 5회 시도·시즌 진행·재접속을 화면의 컨트롤로 실행합니다. 기록 확인은 인증된 서버 저장 조회와 화면의 점수 표시를 사용합니다.

- Chromium: Android/iPhone Instagram UA, 터치·모바일 설정, GPU 비활성화. CDP의 손가락 드래그·누르기로 사인과 킥을 실행합니다.
- Linux WebKit: 모바일·터치 설정과 같은 UA. 버튼·골문은 터치 탭, 사인·킥은 마우스 드래그·누르기로 실행합니다. 실제 iOS의 터치 입력 검증과 구분합니다.
- 기기 저장 속성 차단, 쓰기 용량 오류, 캡처 API 오류, 공유 가능 여부 조회 오류, `roundRect` 미지원, WebGL 미지원 조건을 재현합니다. Chromium에서는 포인터 이벤트를 없앤 터치 대체 경로도 검사합니다.
- 인증 세션 응답을 통제해 쿠키 거부와 Google 인증 안내를 검사합니다. 외부 Google 공급자와 실제 인증을 수행한 검증은 아닙니다.
- PNG 헤더와 780×1180 크기, 이미지 저장 안내 후 URL 유지, JSON 미표시, 앱 높이 844→530px 변경, 임시 저장 상태와 로그인 후 서버 복원을 확인합니다.
- Chromium은 드래그 직후의 아주 빠른 다음 합성 탭을 클릭으로 전달하지 않는 동작이 있습니다. 앱 없이 SVG·버튼만 있는 페이지에서도 재현되어, 드래그 검증 후 450ms 간격을 두고 다음 컨트롤을 누릅니다.

```sh
npm test
npm run build
node tests/browser-server.mjs tests/browser-instagram.py
# Playwright WebKit과 시스템 라이브러리가 설치된 경우:
FOOTBALL_WEBKIT=1 node tests/browser-server.mjs tests/browser-instagram.py
```

이 클라우드에서는 WebKit과 부족한 Debian 라이브러리를 `/tmp`에 내려받아 검증했습니다. 앱 자체에는 새 그래픽 라이브러리나 WebKit 실행 의존성을 추가하지 않았습니다.

## 실제 기기 검증 범위

설치된 Instagram 앱과 iPhone/Android 실기기에서의 사진 앨범 저장은 이 환경에서 검증하지 못했습니다. UA와 엔진을 재현한 테스트는 앱 버전별 사진 저장 메뉴, OS 공유 시트, WKWebView의 정책을 완전히 재현하지 않습니다. 카드 저장 메뉴와 로그인 쿠키가 앱에서 제한되면 Safari 또는 Chrome을 이용해야 합니다. 외부 브라우저에서는 같은 계정으로 로그인해 기록을 복원하며, 비회원 기록은 설정에서 백업해야 합니다.

## 결과

- 단위·엔진·서버: **58개 통과**. 빌드 성공.
- Chromium·WebKit 호환성: **20개 흐름 통과**. 두 엔진 각각 10개 능력치 매핑, 총 **100회 특훈 시도**를 완료했습니다. WebGL을 차단한 상태에서 사인·계약·시즌 진행·서버 복원·PNG 생성이 동작했습니다. 콘솔 오류와 미처리 예외는 0개였습니다.
- 기존 비회원 브라우저 14개, 온라인 브라우저 11개, 보안 브라우저 3개 시나리오가 통과했습니다. 비회원 마우스·온라인 손가락 사인과 PNG 실제 다운로드 두 흐름도 통과했습니다.
