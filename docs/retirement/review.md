# 은퇴 연출과 엔딩 카드 — 2026-10-12

원본 [이번 생은 야구다](https://slbcareer.com/)의 실제 은퇴 화면을 기준으로, 축구 기록에 맞는 은퇴 연출과 앞뒤 카드를 추가했습니다. 소스 보안·최적화 수정은 [별도 검토](../audit/source-review.md)에 기록했습니다.

## 실제 사이트 참고 범위

기존 [실제 완주](../playthrough/review.md)에서 확보한 영구결번·최종 카드·은퇴 프로필을 비교 기준으로 사용했습니다. 이번에는 실제 사이트에 재접속해 공개 화면·새 선수 생성·유소년 진행을 확인하고, 현재 제공되는 클라이언트와 스타일에서 은퇴 단계·대기 시간·카드 구성을 다시 확인했습니다. 이번 작업에서 원본 전체 커리어를 새로 완주한 것은 아닙니다. 원본의 서버 계산식이나 계정 데이터를 복사하지 않았습니다.

| --- | --- |
| 유니폼·이름·등번호·헌정 문구 | [원본 / 구현](comparison-0.png) |
| 점수 구성·전성기 등급·기록 버튼 | [원본 / 구현](comparison-1.png) |

두 화면 모두 Chromium, 390×844 CSS px, deviceScaleFactor=1입니다. 원본은 기존 실제 완주 캡처이며 구현은 아래 신규 완주 테스트의 최종 렌더링입니다. 다른 선수·종목·시즌의 기록 숫자까지 같다는 의미는 아닙니다.

## 구현된 동작

- 자연/선택 은퇴 후 시즌 회고 → 집계 → 최종 카드로 이어집니다. 헌정 조건을 만족하면 앞에 마지막 이야기 → 구단 결정 → 유니폼·등번호·이름 연출을 표시합니다.
- 헌정은 게임 내에서 한 구단의 1군 8시즌 이상, LEGACY SCORE 4,000점 이상인 은퇴 선수에게 제공합니다. 헌정 카드만 금색이고 일반 카드는 파란색입니다. 현실 구단의 영구결번 정책이나 다른 선수의 번호 사용 제한을 뜻하지 않습니다.
- 원본처럼 단계별 3.5초/3초/6.2초 대기, 시즌별 순차 회고, 2초 점수 증가, 뒤이어 능력치 등급 표시를 제공합니다. 줄어든 움직임 설정에서는 빠르게 표시합니다.
- 카드 앞면은 통산 경기·골/선방·도움/클린시트·평점·시간·국가대표 기록과 주요상, 뒷면은 다섯 점수 구성과 전성기 능력치입니다. 클릭·Enter·Space로 뒤집고 수상 목록을 열 수 있습니다.
- 건너뛰기·다시 보기·Escape·Tab 이동을 지원합니다. 탭이 숨겨지면 타이머를 중지하고 돌아오면 이어갑니다. 새로고침하면 회고 진행을 복구하고, 완료한 연출은 강제로 반복하지 않습니다.
- 연출 체크포인트는 계정/선수별 별도 저장 키를 사용합니다. 커리어 원본, 서버 저장 검증, LEGACY 계산식, 대전 점수에 화면 상태를 넣지 않습니다.
- PNG 저장도 금색/파란색과 동일 점수 구성·전성기 기간을 반영합니다. UI의 배경 질감 대신 단색을 사용합니다. JSON 백업은 별도입니다.

## 실행 결과

`npm test` 66개와 `npm run build`가 통과했습니다. 엔딩 테스트 4개는 기존 점수 보존·표시 합계·400개 소수점/포지션 사례·헌정 조건·골키퍼 기록·프로 시즌 없는 선수를 확인합니다.

`FOOTBALL_EVIDENCE_DIR=.local/ending node tests/browser-server.mjs tests/browser-ending.py`에서 저장 파일 편집이나 엔진 직접 호출 없이 실제 화면 버튼으로 비회원 공격수와 온라인 골키퍼를 자연 은퇴까지 진행했습니다. 공격수는 전체 모션과 타임라인 도중 새로고침, 골키퍼는 줄어든 움직임과 건너뛰기를 확인했습니다. 두 선수 모두 카드 뒤집기·뒤집힌 상태의 재생·최종 점수·완료 후 복구·기록 보기·320/430px 가로 넘침 없음·콘솔 오류 없음·커리어 데이터 불변을 확인했습니다. [최종 결과](results.json).

별도로 기존 전체 플레이 테스트에서 네 포지션과 온라인 두 선수의 **여섯 커리어**를 자연 은퇴까지 완료하고 대전 승패·기록을 확인했습니다. [결과 요약](complete-careers.json). 온라인 브라우저 11개, 일반 브라우저 14개, 보안 3개 시나리오, 마우스/터치 사인·PNG 저장 2개 시나리오도 통과했습니다. 테스트는 임시 메모리 DB를 사용해 개발 데이터와 분리했습니다.
